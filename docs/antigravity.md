# Antigravity on Linux

This adapter uses the installed native `agy` CLI. Version 1.5.14 was the original test baseline, not an admission requirement. The router launches it on the execution machine; it does not run a replacement inference service, copy tokens, or implement Google's OAuth exchange.

On Linux 1.5.16, offline tests with disposable signed-out profiles also confirmed the TUI, print, and ACP initialization paths. Managed `agy models` reached the native sign-in check; that test does not verify a signed-in catalog.

## Set up a profile

1. In Accounts, choose Antigravity and add a profile. Its directory is the account root containing `.gemini`, not the `.gemini` directory itself. An existing root must be a private, physical directory owned by the same Linux user. Project files stay in the workspace supplied by the harness.
2. Run `ccp login <id>`. This uses native `agy acp --login`; the browser and pasted-code step belong to Google. The child receives the saved proxy. Your browser uses its own network settings. `ccp login <id> --status` checks for a nonempty, private token file **without reading it**. It does not verify the account email, entitlement, expiry or refresh. To check catalog access, select the profile in Accounts and use **Refresh sign-in status**. It runs native `agy models` in that profile, regardless of which account is the default. A network failure does not mean the profile is signed out. If the profile or its saved login changes during the check, the result is discarded; refresh again.
3. Enable the profile. Configure the harness executable as `ccp` with arguments `["agy","acp"]`, or use the provider-named `agy` launcher link with `["acp"]`. Both accept the same arguments for a new chat or a cold reconnect.

**Connect:** CCP answers `initialize` without choosing a profile or starting AgY. The first `session/new` chooses by policy; `session/load` or `session/resume` chooses the exact ID's recorded owner without advancing rotation. CCP sends that connection's original initialization to the selected native process, checks that it supports the capabilities already advertised, then forwards the session request. Additional sessions on this connection stay on that profile. To work with another owner, open a fresh connection. Explicit `acp --for-session <id>` is still an eager CCP shortcut, not a native AgY option.

**Browse:** Before binding, `session/list` queries enabled profiles on demand. The daemon checks that every enabled profile has a saved login before starting any worker; this does not verify the credentials. It opens one private native ACP worker at a time, follows each native cursor, and closes the worker. The result is one complete page, optionally filtered by exact `cwd`. It preserves up to 64 native `additionalDirectories` per session. Unreadable profiles, failed native reads, duplicate IDs, profile or login changes, and exceeded bounds return an error rather than partial results. Limits: one concurrent browse, 32 enabled profiles, 64 pages per profile, 2,048 total rows, 400 KiB of row data, 8 seconds per profile and 30 seconds total. Inherit uses the daemon's proxy environment for browsing; interactive sessions inherit the launcher's.

After binding, native listing uses only the selected process and preserves its page order, metadata and continuation cursor. Before releasing each page, CCP confirms its IDs and workspaces in one transaction against the connection's owner. An unverified, conflicting or oversized page is refused in full (2,048 rows or 256 KiB of ownership data per page). Both browse modes record newly listed IDs as **Listed by ACP** without recording a startup, changing rotation, or storing titles or additional directories. A listed ID can be resumed immediately or on a fresh connection. Filesystem discovery alone is not ACP evidence.

For model discovery, select a signed-in, enabled Antigravity profile and click **Set as default**. `ccp agy models` (or `agy models` via the launcher symlink) returns that profile's native catalog without advancing rotation or creating a session. Garcon uses this command for catalog discovery and its personal OAuth sign-in check. Changing the default account can take up to a minute to appear in Garcon's catalog cache. Other profiles may have different model entitlements. Successful discovery does not test ACP chat: a harness must skip in-band authentication when the managed server advertises an empty `authMethods` list.

The bridge correlates successful `session/new` responses by request ID and records the returned **opaque** session ID and the requested cwd before exposing the reply. An unknown session, disabled/missing owner, wrong-profile load, or unavailable router is a refusal, never permission to start a replacement session. Native errors, permission requests and client replies stay on the original stdio protocol; launcher diagnostics go to stderr. Frames must be newline-delimited UTF-8 JSON-RPC 2.0, at most 8 MiB, with at most 1024 outstanding requests. Sign in before connecting: the bridge advertises no in-band authentication methods and rejects `authenticate`. This keeps the harness from running a raw terminal login against the desktop identity. Forks, storage overrides and API-key/ADC authentication are not managed launch modes. Disabling a profile refuses subsequent new/load/resume requests without terminating an active session.

## Native terminal UI

For the native terminal UI, run `ccp agy` in the workspace. It inherits the terminal and uses the selected profile's private HOME, bus-less runtime and proxy. The startup log records the profile, not an ID for a new chat.

Independently of the installed CLI version, ccpd watches each registered profile's `.gemini/antigravity-cli/conversations` directory. **Sessions** records a unique owner when a nonempty, user-owned regular file named `<uuid>.db` or `<uuid>.pb` appears. The UUID must be lowercase and hyphenated. Both extensions count once. The watcher checks metadata only, including disabled profiles for conflicts; it does not open transcripts or follow symlinks. It reconciles existing files at startup and periodically, and picks up newly registered profiles and directories created later. A file removed before ccpd can verify it may never be recorded.

**Saved file** is evidence of a file in a profile, not of a TUI, print, or ACP launch that created it. Concurrent starts are never matched to files by time. The copied terminal command is `ccp agy --conversation=<uuid>` without a guessed `cd`; an admitted explicit terminal resume supplies its workspace. Every terminal resume still checks for the file. If it was pruned, its recorded owner remains; duplicate or different owners and disabled owners are refused. A file alone never authorizes an ACP load.

If the same profile also reports that UUID through ACP, Sessions offers both resume commands, each with its own workspace.

AgY [1.5.16 added](https://antigravity.google/docs/changelog?tab=cli) `agy --resume <uuid>` and `agy -r <uuid>` as aliases for `--conversation`. The launcher supports all three for interactive resumes, including with `-i 'follow-up'`. Use `--conversation` on older native builds. An exact UUID is required: `-c` / `--continue` means "most recent" within one native account, not across the router's accounts. Combining print with a resume selector is not supported by CCP.

New and resumed terminal sessions accept local options before or after `--conversation`, for example `ccp agy --conversation=<uuid> --sandbox --mode plan`. Pass `--model`, `--effort`, `--mode`, `--agent`, `--add-dir` (repeatable), or `-i`/`--prompt-interactive` with one value per occurrence. Use `-i 'your prompt'` rather than a bare positional argument. The switches `--sandbox` and `--dangerously-skip-permissions` also accept `=true` or `=false`. Enabling the latter tells native AgY to auto-approve tool permissions. Account, storage and remote overrides are not terminal routing options.

For a one-shot, use `ccp agy --sandbox -p --output-format=json 'your prompt'` or pipe text to `ccp agy --print`. With no prompt argument, the launcher streams text stdin unchanged; an empty pipe or terminal gets the native empty-prompt error instead of opening the TUI. For NDJSON, use `ccp agy -p --input-format stream-json --output-format stream-json`: native AgY reads the stream directly.

Only explicit print launches accept caller-supplied `--settings <value>` or `--settings=<value>`. For example, Finder can use `ccp agy -p 'Find the entry point' --settings '{"permissions":{"allow":["read_file(*)"]}}'` without `--dangerously-skip-permissions`. AgY accepts a JSON object or a file path. Relative paths resolve from the caller's working directory; use the attached spelling for a filename starting with `-`. Supply only trusted settings: they can change tool permissions and other native behavior for this invocation. The override is not saved to the profile.

CCP does not open ACP or assign a session ID to a print launch. AgY 1.5.14 [can still save native history](https://github.com/google-antigravity/antigravity-cli/blob/b9f5bf40b9e9e66f417f7bc6e8c0b22a079bc51a/CHANGELOG.md#L826) and has no documented no-save flag. Such a file can appear in **Sessions** as **Saved file**. Discovery does not attribute it to a print or TUI startup, and CCP never deletes it.

On 1.5.14, `--conversation` [resumes an existing conversation](https://antigravity.google/docs/cli/commands/resume); it does not assign an ID. In a disposable, signed-out Linux profile we tried a fresh UUID directory under `conversations/` and `brain/`, an empty `conversations/<uuid>.db`, and an empty `conversations/<uuid>.pb`. The directories were ignored, the database was rejected as uninitialized, and the protobuf file as too short for ciphertext. In all cases the native CLI ignored the flag. AgY can print its own resume ID on normal exit or expose it to a configured TUI status line. The router neither scrapes terminal output nor replaces the user's status line.

## Credentials and keyrings

Tested 2026-11-22 with Google's [Linux x86-64 1.5.14 archive](https://storage.googleapis.com/antigravity-public/antigravity-cli/1.5.14-5302690847260672/linux-x64/cli_linux_x64.tar.gz); archive SHA-512: `83311d3f354567612dc16c1ae2ea9b503d6f6833aa4e138d39aa229da3f3bb99b0e4d7cca0bce4796b0060d6a51d8113eb7449ed5dc0e7900bf217107ea5bff9`.

On Linux 1.5.17, `agy acp` accepts the two storage flags; terminal chats, print, models and quota do not. CCP does not mount or switch any directories. The rule is the same for every client:

- **ACP, including login and list workers:** pass `--gemini-dir <profile>/.gemini --app-data-dir antigravity-cli`. The first selects the root, including shared native settings under its `config/`; the second is a **relative name** for this app's token, settings, logs and conversations. Tools inherit `HOME` and `XDG_CONFIG_HOME` unchanged from the launcher for chats/login, or from the daemon for browse workers.
- **Terminal UI, exact terminal resume, print, models and quota:** set `HOME=<profile>` on the native child. These commands find the same native state under `$HOME/.gemini`. Passing the ACP flags on a bare 1.5.17 chat is a native argument error.

ACP's **plugin credentials** are separate from the Google login. On Linux 1.5.17 the plugin secret file is `$XDG_CONFIG_HOME/antigravity/plugin-secrets.json` (normally `~/.config/antigravity/plugin-secrets.json` when unset). Profiles using the same caller config directory can share that file. CCP does not copy or merge previously saved plugin secrets; a plugin configured under the old profile-local path may ask you to sign in again.

This selects AgY's storage; it is not a filesystem sandbox. A shell or Git process started by ACP sees the ordinary `~` and can find `~/.gitconfig`. A helper that opens `~/.gemini` directly sees the caller's tree, not the ACP flags. The account's Google login file is:

    <profile>/.gemini/antigravity-cli/antigravity-oauth-token

Separate data roots alone do **not** isolate Google accounts when a Linux Secret Service is visible. In an offline 1.5.14 experiment with a real, unlocked disposable GNOME Keyring:

| Child configuration | Observed result |
| --- | --- |
| Normal D-Bus environment | Looked up the shared Secret Service item with service `gemini`, username `antigravity`. |
| `AGY_ACP_FORCE_FILE_STORAGE=1` | Still read the keyring. The literal switch was not found in the tested binary. cc-profile sets it to `1` on login, ACP and quota subprocesses as an explicit storage preference, not as the isolation mechanism. |
| `ANTIGRAVITY_CREDENTIAL_SCOPE` or a `credential-user-scope` file | Neither tested value stopped the shared lookup. |
| Unset only `DBUS_SESSION_BUS_ADDRESS` | Rediscovered the bus under the existing runtime directory. |
| Change only `XDG_RUNTIME_DIR` | Still connected through the explicit bus address. |
| Set the bus address to a dead socket | Attempted the keyring first, then fell back. Not used by cc-profile. |
| Unset the bus address **and** use a fresh private runtime with no bus socket | Selected file storage immediately. Two profiles each opened only their own dummy token file, with no Secret Service calls. Login startup logged the same backend selection. |

CCP uses the last combination on **the native child only**. It also sets `AGY_CLI_FORCE_FILE_TOKEN_STORAGE=1`, which 1.5.17 recognizes, alongside the older storage preference. Do not rely on either flag alone across versions. The private runtime is created under `CC_PROFILE_TEMP_PATH` or the OS temp directory and removed on normal exit. It is separate from `ccpd.sock` and the persistent account directory. CCP neither installs nor impersonates a Secret Service. Protect the account directory and its backups like a password. `--process-per-session` separates ACP workers; it does not select an account.

In separate offline tests, setting `ANTIGRAVITY_GEMINI_DIR` and `ANTIGRAVITY_APP_DATA_DIR` did not move the ACP session database or logs. Changing HOME did move the default tree; explicit ACP flags moved it predictably. The product is distributed as a binary: Google's [public CLI repository](https://github.com/google-antigravity/antigravity-cli/tree/b9f5bf40b9e9e66f417f7bc6e8c0b22a079bc51a) has release notes, examples and issue reports, not the CLI implementation. See also the [Linux keyring report](https://github.com/google-antigravity/antigravity-cli/issues/1610).

**Why not bind-mount the profile over `~/.gemini`?** A private mount can preserve ordinary `HOME` even for the TUI, without hiding the rest of the host. But it need not preserve host privileges. On this VM, unprivileged `bwrap` with the host root bound read/write and one disposable directory overlaid could reach the host Docker socket (`/_ping` returned 200). Only the calling UID was mapped and `NoNewPrivs` was set; `sudo -n true` failed. CCP does not wrap normal launches in bubblewrap. The more restrictive namespaces in the native test suite are for offline verification only.

## Usage and network

Dashboard and Accounts show the remaining percentage and local reset time for each supported model-pool window inline. An absent reset is unknown, not exhausted. Disabled, unknown, and amount-only buckets are omitted. The daemon refreshes enabled profiles after 24 hours without a successful quota read, even with the panel closed. Opening either page checks for stale data after two minutes instead. **Refresh quota** checks one profile, even if disabled. Both pages share the last successful snapshot; a failed refresh marks it stale and backs off before retry. A profile edit or login change hides the old snapshot. Quota-based new launches refresh stale readings before choosing. They rank only the selected model pool (Gemini Models by default, including ACP), never a sum across pools; exact resumes do not wait. To see the native human-readable report, run `ccp usage <id>`.

The panel runs `agy --output-format json --settings '{"disableSlashCommands":false}' -p /usage`. The terminal runs the same command without `--output-format json`. The session-only [slash-command setting](https://antigravity.google/docs/settings#cli-settings) enables the built-in even when disabled in saved settings. Neither path edits those settings, replaces the status line, sends an ACP prompt, or retries using a model. The commands use the selected profile's private HOME, bus-less runtime and proxy. A missing local login file prevents the lookup; cc-profile checks metadata, not credentials.

Google's [pinned release notes](https://github.com/google-antigravity/antigravity-cli/blob/b9f5bf40b9e9e66f417f7bc6e8c0b22a079bc51a/CHANGELOG.md#L1061) document text and JSON output. The observed [native result](https://github.com/oddessentials/agent-guild/issues/320) and an [independent fixture](https://github.com/depollsoft/MonkeySSH/blob/6c4a1c76e7076277d6a44b4b662584620b8d8b33/test/scripts/agent_usage_probe_test.cjs#L692-L717) show model groups and buckets. The panel accepts only a successful zero-turn `usage` result, within two minutes and 64 KiB of stdout. It caches only normalized model-pool windows, never raw native output or login prompts, and discards results if the profile or login changed during the check. Unlike [CLIProxyAPI's quota collector](https://github.com/router-for-me/Cli-Proxy-API-Management-Center/blob/aef56a47e42254602d1e59b62dccd7df9ec8680c/src/features/quota/providers/antigravity/data.ts#L120), ccp does not need to hold Google OAuth credentials or call an internal provider endpoint.

The custom profile proxy is supplied in both uppercase and lowercase forms of `HTTP_PROXY` and `HTTPS_PROXY` for login, TUI, ACP, and native usage. We tested the following operations on the pinned Linux binary with the real launcher and daemon in a network namespace with only loopback. Local HTTP proxies recorded each CONNECT destination and returned 502 without forwarding traffic.

| Native operation | Traffic observed at the proxy |
| --- | --- |
| `acp --login`, deliberately invalid authorization code | `oauth2.googleapis.com:443` (code exchange). A closed proxy caused the exchange to fail with no direct retry observed. The browser was not part of this test. |
| Signed-out ACP initialization and `session/new` | `play.googleapis.com:443` from both ordinary ACP and a separate `--process-per-session` worker. Disabling telemetry removed these connections. No model request was made. |
| Signed-out `-p /usage`, terminal and dashboard | Play and the native updater. This was startup traffic, **not** a successful quota fetch. |

Custom mode used only the saved proxy for those connections. Inherit mode used the shell proxy from the terminal and the daemon proxy from the dashboard. Direct mode hit none of the recorders; native controls attempted the synthetic destination addresses directly. This is evidence for an `http://` proxy on 1.5.14, not a guarantee for all transports, authenticated proxies, or TLS connections to the proxy itself. Configure the login browser separately. Enforce any mandatory no-direct-egress policy outside cc-profile; Antigravity's `sandboxProxy` is for sandboxed terminal commands.

Antigravity also supports a Gemini Developer API key and enterprise ADC. These use different identity/billing mechanisms, not the personal subscription allowance. Google's ACP guide documents Gemini for arbitrary clients; third-party models are restricted to specified editors. The user's harness should identify itself honestly. CLIProxyAPI takes a different approach: its [authenticator](https://github.com/router-for-me/CLIProxyAPI/blob/6eb8554f0ede597b2aa3e508ffb3f111d3c2b9e6/sdk/auth/antigravity.go#L35) manages per-account tokens and its [executor](https://github.com/router-for-me/CLIProxyAPI/blob/6eb8554f0ede597b2aa3e508ffb3f111d3c2b9e6/internal/runtime/executor/antigravity_executor_execute.go#L27) makes upstream requests. That is not how native ACP files work and is not used here.

Primary references: [native sign-in and SSH OAuth](https://antigravity.google/docs/install), [ACP](https://antigravity.google/docs/ide/extensions/acp), [native quota](https://antigravity.google/docs/cli/commands/usage), [headless slash commands](https://antigravity.google/docs/cli/headless), [TUI status-line JSON](https://antigravity.google/docs/cli/statusline), and [Google's terms](https://antigravity.google/terms). Status-line JSON is not an on-demand ACP quota API. A supported native client integration is not permission to replay subscription tokens or bypass provider limits.

**Verification boundary:** the real binary tests used disposable homes, no real Google credentials or paid model turns. File selection and the proxy connections above were verified. Successful two-account OAuth writes, renewal, identity after restart, and proxy use for authenticated model streams or live quota still require an operator acceptance test. Sign in to two accounts separately, restart the launcher and daemon, and load a saved session from each using its original owner. Recheck these behaviors when changing the native version.
